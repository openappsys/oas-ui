# 性能基准（OAS-UI）

> 状态：2026-10-08 刷新（对齐 `docs/perf-baseline.json` 当前档）。
> 结构化数据（机器可读）见 [`docs/perf-baseline.json`](./perf-baseline.json)（生成物，由 `scripts/perf/` 写入）；本文档是对比口径、对照与预算依据的说明。
> 对应原则：`docs/vision.md` §5.8「性能领先」——性能可测量、有基准、有门槛（CI 体积预算），对自身基线逐版本不退化、持续更优。

## 1. 量纲与口径

| 项         | 口径                                                                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 压缩       | gzip = zlib 默认档；brotli = zlib q11（HTTP/1.1 CDN 常见档）                                                                                                   |
| 全量入口链 | `import '@oas-ui/ui'`（dist/index.js）的静态 import 闭包，逐文件压缩求和（**上界估计**：浏览器原生 ESM 逐文件加载的上界，经打包器合并后单文件 gzip 更低，见 cdn.js） |
| 单组件链   | `import '@oas-ui/ui/<目录>'` 的静态 import 闭包（入口 + 依赖），逐文件压缩求和（同上，为上界）                                                                 |
| 渲染耗时   | happy-dom 合成环境（非真实浏览器渲染口径），100 次迭代的均值/中位数/p95（ms）                                                                                  |
| 基线日期   | 2026-10-08（体积），node v23.x                                                                                                                  |

**口径定位（防误读）**：`cdn.js`（单文件全量 bundle）与「全量入口链」都是**便利路径 / 上界估计**，代表「引入全部组件」的极端场景，**不代表单次消费的产品大小**；生产环境应按需引入单组件链（见 §2 tree-shaking 叙事）。

刷新命令：先 `pnpm build`，再 `pnpm perf:size` / `pnpm perf:bench`（两脚本各自 merge 写回同一个 JSON，互不覆盖；**默认只测不写**，更新数据加 `--update-baseline`）。

| 组件   | 入口                        | 文件数 | gzip       |
| ------ | --------------------------- | ------ | ---------- |

**tree-shaking 叙事成立（2026-10-08 图标库 opt-in 后增强）**：按需引入单组件链 gzip 24.8~~39.6 KB，仅为全量入口（912.3 KB gzip）的约 **2.7~~4.3%**；且**不再背整套图标**——单组件链只含其自身所需的少量图标 path。

**固定开销拆分**（以 button 链为例）：

- @oas-ui/core 基类运行时 ≈ 13.5 KB gzip；
- 图标：**仅含自身所需的精确 path**（不再含全量注册表）——2026-10-08 图标库 opt-in 后，button 链 **34.1 → 24.8 KB**（卸掉整套 47 图标 ≈ 9.5 KB）；全量入口 `@oas-ui/ui` 仍自动注册全量集，开箱即用不变。

## 3. 自评摘要

### 体积（2026-10-08）

| 口径           | 实测                                         | 自评                                                                                        |
| -------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 全量           | cdn.js 627.5 KB；全量入口链 912.3 KB（上界） | 天花板 730/1080 KB 内随能力增长，预警线 657/972 KB（§4）                                     |
| 按需（button） | 24.8 KB（含 core；图标仅精确 path）          | 预算 29 KB 的 **86%**；图标库 opt-in 后卸掉整套图标（34.1→24.8 KB）                           |
| 按需（table）  | 92.6 KB（链含 core + virtual-list + i18n + 分页 + 导出/移动降级/编辑器通道） | 预算 108 KB 的 86%；`/core` 纯核路径为瘦身消费者预留（见 architecture §3.1）              |
| 主题           | 3.5 KB gzip（index.css）                     | 一套语义 token 变量即全部主题成本；组件样式内联进组件，无独立样式文件                        |
| 可选运行时     | glass-fluid.js 7.8 KB gzip（独立档）         | 预算 8.5 KB 的 92%（已达 WARN 预警线）；独立可选、不进 union                                |
| 图标集         | 组件链只含精确 path；全量集 10.9 KB gzip     | 图标库 opt-in：全量入口自动注册（开箱即用），按需链不背整套                                   |

### 渲染耗时（happy-dom，median/p95，ms）

| 场景                          | 门槛（§4 渲染预算） |
| ----------------------------- | ------------------- |
| button 首渲染                 | 5 ms                |
| table 100 行首渲染            | 50 ms               |
| select 100 选项首渲染         | 50 ms               |
| table 数据更新（100 行换新）  | 50 ms               |
| select 选项更新（100 项换新） | 50 ms               |

> 渲染口径诚实声明：happy-dom 无排版/合成管线，数值仅供**相对对比与退化监测**；真实浏览器首帧数字需另行用 Playwright/Lighthouse 建立基线后评估。渲染段数据由 `pnpm perf:bench` 写入 JSON，不进 CI。

### 结论（对照 vision §5.8）

1. **体积**：按需口径（24.8~~39.6 KB/组件）保持轻量；全量口径在两层制预算内随组件能力增长，纪律由单组件链绝对值预算守住。
2. **渲染**：合成环境数据仅作退化监测；真实浏览器基线待补。
3. **已完成 / 已知优化方向**：
   - **图标库 opt-in（已完成 2026-10-08）**：全量集从组件链解耦——组件链只含自身所需图标 path（不再背整套 47 图标），全量入口 `@oas-ui/ui` 自动注册保持开箱即用；按需模式用内置图名需 `import '@oas-ui/icons/register'` 一次。收益：button 34.1→24.8、table 101.6→92.6 KB；
   - 提供官方按需打包配置示例，帮助消费者吃到 tree-shaking；
   - 新 L3 能力子包（大表面能力）按同机制以子路径隔离体积（见 `docs/architecture.md` §3.1）。

## 4. 预算与门槛

### 体积预算（CI 强制，`pnpm perf:size` 超预算非零退出）

**两层制（2026-08-23 定夺，2026-10-08 重定档）**：

- **全量类 = 天花板制**（cdn.js / 全量入口链）：组件能力持续增强，体积随之增长属预期内行为，天花板只为防灾难性膨胀；达 90% 预警线（WARN，不拦截）时启动瘦身评估或再定档；
- **单组件链与 theme / 可选运行时 = 绝对值制**（实测 + 上浮约 15~20%）：守住按需引入叙事的纪律，超预算即 FAIL。
- **可选层零泄漏（结构断言）**：任何可选层文件（`glass-fluid.js` / `glass.css` / `skins.css` 等）都**不得出现在基础链（全量入口链与各单组件链）的可达文件清单**里——新增可选层不必新增预算行，泄漏即报红。

| 预算项                    | 实测 gzip | 预算（制式）          | 依据                                                                                          |
| ------------------------- | --------- | --------------------- | --------------------------------------------------------------------------------------------- |

| table 链                  | 92.6 KB   | 108 KB（绝对值）      | 2026-10-08 重定档（同上）；含 core + virtual-list + i18n + 分页 + 导出/移动降级/编辑器通道      |

### 渲染预算（本地/发布前，`pnpm perf:bench` 量级防退化）

阈值取多轮实测 p95 的约 3~5 倍取整（happy-dom 下耗时跨轮次波动明显）：button 5 ms / input 15 ms / table 100 行 50 ms / select 100 选项 50 ms / tabs 10 面板 15 ms / form 10 字段 40 ms / table 数据更新 50 ms / select 选项更新 50 ms。渲染耗时波动大，**不进 CI**。
